## SECTION 1: EXECUTIVE SUMMARY

**Product Name:** Dayflow - Human Resource Management System
**Timeline:** 8 hours
**Target Users:** Employees & HR/Admin staff
**Core Value:** Streamline HR operations with role-based access and approval workflows

---

## SECTION 2: PRD - PRODUCT REQUIREMENTS DOCUMENT

### 2.1 Purpose & Scope
To create a functional MVP (Minimum Viable Product) HRMS that handles:
- User authentication (Sign Up/Sign In)
- Role-based dashboards (Admin vs Employee)
- Employee profile management
- Attendance tracking
- Leave management with approval workflow
- Payroll visibility (read-only)

### 2.2 Core Features (MVP Only)

#### Feature 1: Authentication & Authorization
- **Sign Up:** Email, Password, Employee ID, Role selection
- **Sign In:** Email & password login
- **Security:** Basic password validation, session management
- **Priority:** CRITICAL (must complete first)

#### Feature 2: Dashboard (Role-Based)
**Employee Dashboard:**
- Quick access cards: Profile, Attendance, Leave Requests, Logout
- Welcome message with name

**Admin Dashboard:**
- Employee list view
- Pending leave approvals count
- Navigation to each section

#### Feature 3: Employee Profile
- View personal details (Name, Email, Employee ID, Phone, Address)
- View job details (Department, Position, Joining Date)
- View salary structure (Basic, Allowances, Deductions) - read-only
- Profile picture display
- Edit functionality for employees (phone, address only)
- Admin can edit all fields

#### Feature 4: Attendance Management
- Daily attendance view with status (Present/Absent/Half-day/Leave)
- Weekly summary view
- Check-in/Check-out timestamps for current day only
- Read-only for employees (own attendance only)
- Admin can view all employees' attendance

#### Feature 5: Leave Management
**Employee:**
- Apply for leave (type, date range, remarks)
- View leave request status
- Leave balance display

**Admin:**
- View all pending leave requests
- Approve/Reject with comments
- View leave history

#### Feature 6: Payroll Management
- Employee: View only own salary structure & salary history
- Admin: View all employees' payroll data

## SECTION 3: USER FLOWS

### Flow 1: User Registration & Login
1. User lands on Sign Up page
2. Enters Email, Password, Employee ID, selects Role (Employee/Admin)
3. Password validation (min 8 chars, 1 uppercase, 1 number)
4. Account created → Redirect to Sign In
5. User logs in with credentials
6. Role-based dashboard loads

### Flow 2: Employee Views Profile
1. Employee clicks "Profile" from dashboard
2. Personal/Job/Salary details load
3. Edit button available for limited fields
4. Admin can access any employee profile from list

### Flow 3: Employee Applies for Leave
1. Employee clicks "Apply Leave"
2. Select leave type (Paid/Sick/Unpaid)
3. Choose date range
4. Add remarks
5. Submit → Status shows "Pending"
6. Admin notification badge updates

### Flow 4: Admin Approves Leave
1. Admin sees pending requests on dashboard
2. Clicks on request → Details open
3. Can approve/reject with comments
4. Employee sees updated status in real-time

## SECTION 4: DATA MODEL (Simplified)

```
Users Table:
- user_id (PK)
- email
- password (hashed)
- employee_id (unique)
- role (Employee/Admin)
- created_at

Employee Table:
- employee_id (PK)
- first_name, last_name
- department, position
- phone, address
- joining_date
- salary_basic
- salary_allowance
- salary_deductions

Attendance Table:
- attendance_id (PK)
- employee_id (FK)
- date
- status (Present/Absent/Half-day/Leave)
- check_in, check_out
- remarks

Leave Table:
- leave_id (PK)
- employee_id (FK)
- leave_type (Paid/Sick/Unpaid)
- start_date, end_date
- status (Pending/Approved/Rejected)
- remarks
- admin_comments
- created_at

Salary Table:
- salary_id (PK)
- employee_id (FK)
- month, year
- basic, allowance, deduction, net
- created_at
```

## SECTION 6: TECHNICAL REQUIREMENTS

### Tech Stack (Recommended for 8-hour sprint)
- **Frontend:** React + Tailwind CSS (or basic CSS)
- **Backend:** Node.js + Express (or use Firebase/Supabase)
- **Database:** PostgreSQL/MySQL or Firebase Firestore
- **Authentication:** JWT or Firebase Auth
- **Hosting:** Vercel (Frontend), Heroku/Railway (Backend)

### Non-Functional Requirements
- Load time < 2 seconds
- Mobile responsive
- Data encryption for sensitive fields (password)
- Session timeout after 30 mins inactivity
- Basic error handling & validation

## SECTION 12: GLOSSARY

- **MVP:** Minimum Viable Product - smallest working version
- **JWT:** JSON Web Token - for secure authentication
- **CRUD:** Create, Read, Update, Delete operations
- **Role-based Access:** Different features based on user role
- **Status:** Current state (Pending, Approved, Rejected, etc.)
- **Payload:** Data sent in request body
- **Token:** Authentication identifier stored in browser
